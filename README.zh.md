# NMGLFDFS

**NMGLFDFS**（*No More Good Life For Decrypting File System*）是一个面向 Linux x86-64 的独立加密文件系统。它不是 Btrfs 的补丁：它是独立的镜像和独立的代码，但其磁盘布局有意以简化的方式借鉴了 Btrfs 的思路（超级块、元数据 B 树、写时复制、校验和）。

代码用 **NASM**（x86-64，Linux 系统调用）编写。没有内核模块：挂载通过底层 `/dev/fuse` 协议在用户空间完成。唯一的外部辅助程序是系统工具 `fusermount3`，它执行非特权的 `mount(2)` 并移交设备文件描述符。FUSE 协议本身由 NASM 代码解析和应答，不使用 libfuse，也没有自己的 C 代码。

## 构建

需要 `nasm`、`ld`，挂载时还需要 `fusermount3`（`fuse3` 软件包）以及对 `/dev/fuse` 的访问权限。

```bash
make
make test
```

`make` 会构建：

| 程序 | 用途 |
| --- | --- |
| `mkfs.nmglfdfs` | 创建镜像 |
| `nmglfdfs` | 挂载镜像 |
| `nmglfdfs-ctl` | `sleep`、`wake`、`wipe` |
| `nmglfdfs-selftest` | 加密与文件系统自检 |

## 使用

口令通过环境变量 `NMGLFDFS_PASSPHRASE` 或 `-p` 参数提供。

```bash
export NMGLFDFS_PASSPHRASE='secret-phrase'
./mkfs.nmglfdfs image.img 64
mkdir -p /mnt/nmgl
./nmglfdfs image.img /mnt/nmgl
# 在另一个终端：
echo hello > /mnt/nmgl/file.txt
ls /mnt/nmgl
fusermount3 -u /mnt/nmgl

./nmglfdfs-ctl sleep image.img    # 元数据被隐藏，普通挂载会被拒绝
./nmglfdfs-ctl wake  image.img    # 用同一口令恢复
./nmglfdfs-ctl wipe  image.img    # 不可逆地销毁密钥
```

`sleep` 是可逆的：指向树根的指针和被包裹的密钥会用一个由口令派生的独立密钥封存，超级块的工作字段被清零。只要 SLEEP 标志被设置，`nmglfdfs` 就不会打开文件——必须显式执行 `wake`。

`wipe` 是不可逆的。随机的文件系统密钥仅保存在超级块中，并用口令加密。`wipe` 会清除该字段、盐值、校验码以及元数据树节点。即便知道口令也无法恢复密钥，数据块仍是无法读取的密文。

## 一个数据块如何被加密

对每个 4096 字节的文件块，在写入时读取毫秒级时间。最后一位数字（`timestamp % 10`）选择十种方法之一。与此同时，在加密后的 B 树叶子中，extent 记录会保存时间戳、写入代号、方法索引、明文的 CRC32C，以及截断为 16 字节的密文 HMAC-SHA256。该标签由数据密钥计算，并绑定到块号、inode、偏移量和 extent 字段。读取时会在解密前验证它：被篡改的字节会导致 I/O 错误。没有元数据密钥，这些字段本身也无法读取。

**加密**顺序：

1. **位翻转。** 对数据密钥、时间戳、代号、文件内偏移量和 inode 号计算 SHA-256，并用它为 ChaCha20 播种。对每个字节 `i`，取时间戳位 `(timestamp >> (i mod 64))` 以及时间戳中置位比特数的奇偶性。如果二者异或为 1，则整个字节取反（`NOT`），而这一切都叠加在 ChaCha20 密钥流之上。该操作是它自身的逆运算，并由存储的时间戳唯一确定。
2. **十个可逆层之一**（见下文）。
3. **ChaCha20**，其 SHA-256 子密钥包含方法号、时间戳、代号、偏移量和 inode。块计数器为 1，使密钥流不与位翻转步骤重合。

解密按相反顺序进行。方法索引必须与所存时间戳的最后一位匹配。

十个层（全部可逆，ChaCha20 在其前或其后）：

| 数字 | 层 |
| --- | --- |
| 0 | 每个 `u64` 乘以一个奇数常量，对 2^64 取模 |
| 1 | Feistel 网络，4 轮，32 位两半 |
| 2 | 每个 `u64` 内的双射位置换 |
| 3 | 在 GF(2^8) 中进行字节乘法（AES 多项式）并与常量异或 |
| 4 | AES S-box 替换 |
| 5 | ARX：加法、循环移位、异或 |
| 6 | 半字节交换、对 256 取模加法、与索引异或 |
| 7 | GF(2) 上的 AES 仿射变换 |
| 8 | 对 16 字节的 Feistel 网络，64 位两半 |
| 9 | 对每四个字节执行 AES MixColumns |

数据密钥和元数据密钥由一个随机的 32 字节文件系统密钥派生。它在 `mkfs` 时创建（`getrandom`），并以 ChaCha20 加密后存入超级块。加密该字段的密钥来自 PBKDF2-HMAC-SHA256（200000 次迭代，盐值在超级块中）。迭代次数写在超级块里，因此已创建的镜像会以自己的次数打开。

完整的磁盘布局见 [docs/FORMAT.md](docs/FORMAT.md)。

## 关于安全性的坦诚说明

安全性设想依赖于 **ChaCha20**，以及文件系统密钥是随机的且会被 `wipe` 销毁。数学层如方案作者所愿增加了扩散，但它们**不能替代经过审计的密码学**。这是一个学习用原型：

- 其中的 ChaCha20、SHA-256、HMAC 和 PBKDF2 实现是在此用 NASM 编写的，**未经审计**；
- 该模式（位翻转 + “毫秒数字” + 自定义子密钥）**不是**标准的 ChaCha20-Poly1305：认证是一个截断为 16 字节的独立 HMAC-SHA256，而非 Poly1305；
- 200000 次 PBKDF2-HMAC-SHA256 迭代是现代的通常最低值，但仍应避免使用弱口令；
- 无法防止将整个镜像回滚到旧副本：标签能捕捉字节篡改，却无法防止用旧版本整体替换文件；
- `sleep` 对普通挂载隐藏密钥，但被封存的数据块仍留在磁盘上，可用同一口令通过 `wake` 重新打开。

不要在这个原型中保存你不愿丢失或泄露的数据。

## 原型的局限

- 没有快照、硬链接、符号链接、扩展属性，也没有作为独立结构的稀疏文件（空洞在被写入前读取为零）。
- 空闲空间是位图，而非 Btrfs 的 extent 树。超级块就地写入（两份副本：块 0 和块 1）。抗崩溃能力是尽力而为：新节点在根指针移动之前写入，但这不是完整的日志。
- 一个内部节点最多容纳 101 个子节点。满节点会一分为二，如果它是根节点，树会增长一层。当镜像用尽块或深度达到八层时，答案仍是“没有空间”。
- 单个 FUSE 请求处理线程。包含数千个文件的目录通过完整的树遍历来读取。
- 创建时的镜像大小为 4 到 2048 MiB。

## 测试

`make test` 运行 `tests/run_tests.sh`：自检（全部 10 种方法、位翻转确定性、SHA-256 / ChaCha20 / CRC32C / PBKDF2 的已知答案测试、写入与读取、重新打开、B 树增长到新层级以及非根内部节点的分裂、重新读取、翻转密文字节后以及篡改节点并重算 CRC 后的读取失败、`sleep`/`wake`/`wipe`），若存在 `/dev/fuse`，还会运行端到端挂载场景。
